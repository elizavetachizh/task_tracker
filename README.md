# Трекер задач

Доска из трёх колонок: «Новая», «В работе», «Готово». Задачи хранит PostgreSQL, API отдаёт NestJS, экран собран на React.

Нужны Docker и Node.js 24.

## Запуск всего проекта в Docker

Из корня репозитория:

```bash
docker compose up --build
```

- Доска: [http://localhost:5173](http://localhost:5173)
- API: [http://localhost:3000](http://localhost:3000)
- Проверка API: `GET http://localhost:3000/api` отвечает `{ "status": "ok" }`

При старте контейнер API применяет миграции. Данные Postgres лежат в volume `task_tracker_postgres`.

Остановить:

```bash
docker compose down
```

## Локальная разработка

Postgres в Docker, API и доска на хосте. Контейнер API при этом не поднимать: он занимает тот же порт `3000`.

```bash
docker compose up -d postgres
```

API, из каталога `backend`:

```bash
cp .env.example .env
npm install
npm run migration:run
npm run start:dev
```

Доска, из каталога `frontend`:

```bash
npm install
npm run dev
```

Dev-сервер Vite проксирует `/api` на `http://localhost:3000`. Файл `frontend/.env.development` оставляет `VITE_API_URL` пустым, поэтому браузер ходит на тот же origin.

## Тесты

```bash
cd backend && npm test
cd frontend && npm test
```

Тесты сервиса задач не требуют базу: репозиторий замокан. `npm run test:e2e` в `backend` поднимает приложение и проверяет `GET /api`, для этого нужен Postgres из `.env`.

## Решения

- Один экран на Vite и React 19. Next.js не использовался: маршрутов и SEO нет.
- Стили — тема MUI и `sx`, без отдельного CSS-фреймворка. Шрифт Inter.
- Фронт меняет данные только через `frontend/src/api`. После создания, правки, переноса и удаления список запрашивается заново.
- Бэкенд — NestJS, TypeORM и PostgreSQL 16. Схема меняется миграциями.
- Одна таблица `tasks`. Порядок в колонке задаёт `position`, при равенстве — `createdAt`. Новая задача и перенос в другую колонку ставят карточку в конец.
- Статус меняет только `PATCH /api/tasks/:id/move`. Обычный `PATCH` правит название, описание и приоритет.
- Валидация на входе: лишние поля дают `400`, неизвестный id — `404`. Подписи колонок и приоритетов живут на фронте, в API уходят `new`, `in_progress`, `done` и `low`, `medium`, `high`.

## Ограничения

- Нет пользователей, авторизации и нескольких досок.
- Нет поиска, фильтров и постраничной загрузки.
- В Docker у фронта вшит адрес API `http://localhost:3000`: страница открывается с машины, где проброшены порты. Пароль базы `task` / `task` годится только для локального запуска.
- Полный сценарий «создать → перенести → удалить» покрыт ручной проверкой и тестами сервиса, не отдельной e2e-базой.

## Улучения

- Перетаскивание мышью между колонками и изменение порядка внутри колонки.
